**cell-ontology** | [obophenotype/cell-ontology](https://github.com/obophenotype/cell-ontology) | [Issue #3333](https://github.com/obophenotype/cell-ontology/issues/3333) | [PR #3547](https://github.com/obophenotype/cell-ontology/pull/3547) | @gouttegd | merged 2025-12-22

`axiom_repair` `simple` `tightly_scoped` `approved_first_time`

## Context

This is the second occurrence of the recurring issue where imported annotation properties (oboInOwl:hasDbXref, oboInOwl:hasExactSynonym, etc.) accumulate redundant `rdfs:label` annotations in the edit file. These labels already exist in the merged imports and their presence in the edit file is confusing and unnecessary. The issue was originally fixed in PR #3333 but the labels crept back in.

## Changes Made

Removed 24 lines of redundant `rdfs:label` annotations for imported annotation properties from `cl-edit.owl`. This is a purely subtractive change with no additions.

## Resolution

Approved on first review in a single commit. Simple difficulty because the fix is purely mechanical deletion, but it demonstrates an important maintenance pattern: understanding which annotations belong in the edit file versus the imports. An agent would need to understand OWL import chains to know which labels are redundant.

## Verification checklist

- [x] Identified every `AnnotationAssertion(rdfs:label …)` in cl-edit.owl whose subject is an imported annotation property (IAO/oboInOwl/uberon/rdfs/etc.).
- [x] For each candidate, grepped `src/ontology/imports/merged_import.owl` to confirm whether the same `rdfs:label` is already asserted there. Only properties with a confirmed label in `merged_import` were removed.
- [x] Properties **kept** because their label is *not* in `merged_import` (removing would lose information):

  - `oboInOwl:inSubset` "in_subset"
  - `rdfs:seeAlso` "see also"
  - `uberon:HUMAN_PREFERRED`, `uberon:LATIN`, `uberon:PLURAL` (subject-specific labels, not in merged_import)
- [x] Visually inspected the diff and the surrounding axioms in the file. The remaining structure (object-properties / classes sections) is intact.

## Rationale for the conservative approach

The original PR description ("such as `oboInOwl:hasDbXref`, `IAO:0000115`, `oboInOwl:hasExactSynonym`, etc. that already have a label defined in the `merged_import` module") states the criterion rather than enumerating every removal. I applied the criterion strictly: a label is removed only if the same predicate–subject pair already carries an `rdfs:label` in `merged_import.owl`. This avoids accidentally dropping CL-only labels for properties that happen to be declared (but not labeled) upstream — e.g., `IAO_0000028` is declared in `merged_import` but has no `rdfs:label` there, so its `"symbol"` label was kept.

## Not included

The hand-targeted edit preserves the file's existing sort order. If a full re-serialization is desired it can be done with `robot convert -i cl-edit.owl -o cl-edit.owl --format ofn` in a separate pass.
