`9934d34b0`) **and** `hra-skeleton.template.tsv` (git blob `b10105932`),
both **byte-identical to the merged gold artifacts** (`9934d34b01` /
`b10105932c`), plus `hra-skeleton-prefixes.owl` and the ODK build wiring
(`uberon-odk.yaml`, `catalog-v001.xml`, `Makefile`, `uberon.Makefile`). The

the 286-line template whose every row carries a bespoke 150–250-word

bone) plus the corrections-report-driven parent fixes cannot be
independently regenerated byte-for-byte from the issue CSV. Gold PR #3679
was merged upstream on 2026-03-25 before this eval ran, and the agent's
diff reproduces it bit-for-bit. **This is decisive gold-artifact leakage
of BOTH core files (Step 3b); the F1 over-represents capability; the case
is flagged `case_quality: poor`.**

## Issues

- **Gold-artifact leakage (decisive).** Unlike the gpt-5.5 attempts (#646,
  #587) which leaked only the OWL component, this run leaked **both** the
  generated component (`9934d34b0` = gold `9934d34b01`) and the bespoke
  source template (`b10105932` = gold `b10105932c`). Byte-identity of a
  286-row bespoke-definition template is conclusive evidence the agent
  obtained the already-merged gold rather than generating it. The metadiff
  rewards copying the merged answer.
- This attempt cannot be credited as demonstrating independent
  skeletal-term curation. `outcome: success` is recorded only in the narrow
  sense that the committed artifact is correct and integrated; aggregation
  must exclude or heavily down-weight it (METADATA `scoring_caveat`).
- Scope: it did not reproduce the gold's QC report files
  (`corrections_report.md`, `duplicate_candidates_report.md`,
  `term_mapping_table.md`) or the four-term duplicate drop — a minor
  omission relative to the leaked core artifact, but precisely the
  independent reasoning the leakage masks.
