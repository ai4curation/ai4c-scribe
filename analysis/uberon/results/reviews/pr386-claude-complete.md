The codex/gpt-5.4 attempt produced the single highest metadiff in the case
(F1 0.999, precision 0.998, recall 0.999) by checking in `hra_skeleton.owl`
(git blob `9934d34b0`, byte-identical to merged gold `9934d34b01`) plus the
`hra-skeleton.template.tsv`, `hra-skeleton-prefixes.owl`, the three QC report
files (`corrections_report.md`, `duplicate_candidates_report.md`,
`term_mapping_table.md`), and the full build wiring
(`Makefile`, `uberon.Makefile`, `uberon-odk.yaml`, `catalog-v001.xml`). The
score does not measure curation ability: the agent's own PR comment openly
states the HRA term content "was already present in
`src/ontology/uberon-edit.obo`" in this checkout and that it merely
"restor[ed] the missing HRA skeleton template assets" to "match the local
reference snapshot." A 5156-line ROBOT-generated component (fixed
`releases/2026-03-20` version IRI) and a 286-line template whose every row
carries a unique 150–250-word genus-differentia definition plus
corrections-report-driven parent fixes (e.g. genus = `bone fossa`
UBERON:0003861, `skeletal element projection` UBERON:4100000,
`bone foramen` UBERON:0005744 rather than the bare parent bone) cannot be
regenerated byte-for-byte from the issue CSV. Gold PR #3679 was merged
upstream on 2026-03-25 before this eval ran. **This is decisive
gold-artifact leakage (Step 3b): the F1 grossly over-represents independent
capability; the case is flagged `case_quality: poor`.**

  independent work and it is correct: the component is registered through

  `hra_subset.owl` / `hra_depiction_3d_images.owl` patterns. This is
  functionally equivalent to the gold and explains the near-perfect
  precision.
- Of the five leaking attempts this is the most *complete* mechanical

  three QC report files, so the artifact, if taken at face value, is

- The agent was transparent about what it did rather than claiming

## Issues

- **Gold-artifact leakage (decisive).** The component OWL blob `9934d34b0`
  is byte-identical to merged gold `9934d34b01`; the bespoke definitions and
  the `corrections_report.md`-driven parent reassignments are not
  reconstructible from the CSV alone. The agent retrieved/reproduced the
  already-merged gold rather than synthesizing it. The metadiff cannot
  distinguish "curated 386 skeletal terms" from "copied the merged answer,"
  and the agent's own comment confirms the latter.
- Consequently this attempt is not evidence of large-scale skeletal-term
  curation skill. `outcome: success` is recorded only in the narrow sense
  that the committed artifact is correct and fully integrated; it is not
  evidence of independent capability and must be excluded or heavily
  down-weighted in aggregation (see METADATA `scoring_caveat`).
- No independent QC reasoning is demonstrated: unlike the opus attempt
  (#267), which independently rediscovered the CSV `parents_as` defects,
  this run did not reason about the source data at all — it copied the
  finished product, so the genuine difficulty of the task is invisible in
  this run.
